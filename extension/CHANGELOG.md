# 変更履歴

## 0.7.3

**「記録に無い稼働中の機体」の行で、起動元が右端に消えていたのを直した。** 0.7.2 で足した
情報が、画面では読めていなかった。この欄は1行に収める作りで、溢れた分は「…」になる。

- 素性（説明・起動元）を先、様子（モデル・ツール・回数）を後に並べた。実測（幅1500px）:
  直す前は `北側の起伏を測る / haiku / Grep slope / ツール 2 …` で起動元が消えていたが、
  直した後は `北側の起伏を測る / 起動元 地形の起伏を測る / haiku / …` になる。
- 消えてよいのは「いま何をしているか」で、次の更新でまた出る。「どの機体か」
  「誰が起動したか」は消えてはいけない——この欄はそれを読むためにある。

## 0.7.2

**「記録に無い稼働中の機体」に、それが何者で、誰が起動したのかを出すようにした。**
あの欄はエラーではなく「対応づけに確信が持てなかった」という申告なのに、出ているのが
モデル名とツール名だけで、なぜ結ばれなかったのかも、どの機体なのかも読めなかった。

- **その機体の説明（Agent ツールへ渡した description）を出す。** 値は前から読めていて、
  画面が捨てていただけだった。`--name` をこれに合わせれば対応づけの規則1で必ず結ばれるので、
  直し方が画面から直に読める。実際に、`--name` に班名の接頭辞を付けたせいで3体まとめて
  結ばれなかったことがあり、そのとき画面からは原因が分からなかった。
- **起動元を実測で辿って出す。** `meta.json` の `toolUseId` はその機体を起動した Agent
  呼び出しのIDで、同じIDは親の記録に `tool_use` として現れる。**推測ではない。**
  手元の全記録で確かめたところ、孫にあたる 15 体すべてがちょうど1体の親に解決し
  （自己参照なし）、その呼び出しのツール名は 15/15 とも `Agent` だった。
- 走査は1本も増えていない。`tool_use` は稼働中の読み取りが毎回すでに読んでいるブロック
  そのものなので、そこで起動呼び出しのIDを拾うだけで済む。
- **系統樹には線を引かない。** 親が実測で分かっても、どの世代のどこに置くかには推測が
  入る。親が辿れなかった機体に「指令塔」などと補うこともしない。分からないことは
  分からないまま出す、という方針は変えていない。
- 検査に「記録に無い機体に、実測した起動元が載る」を新設した（7項目）。合成データだけで
  判定するので、そのマシンに何が残っているかに左右されない。

## 0.7.1

**0.7.0 で配った .vsix を、同じ版番号のまま差し替えたのが届かなかった。** 拡張は同梱の
本体を `~/.claude/agent-dashboard/` へ配置し、そこから画面を出す。その配置には版番号の
関門があり（`extension.js`: 配置済みの版が同梱の版**以上**なら何もしない）、0.7.0 のまま
中身だけ差し替えても、すでに 0.7.0 を入れた環境には**構造的に届かない**。実際、入れ直しても
画面は古いファイルのままだった。中身の差し替えには必ず版番号を上げる。

- **出口を行き先の高さへ寄せるとき、隣の出口を追い越さないようにした。** 辺は行き先の高さの
  昇順に出口を割り当てていて、その順序そのものが交差ゼロの前提になっている。ところが
  「差が小さいときは高さをそろえて水平1本で届かせる」最適化がその順序を壊すことがあり、
  追い越された辺は反対側へ回るので、必ず相手の水平線を横切る。実測では 5世代45体のダミーで
  2組が交差し、別の3組は出口が 1〜3px しか離れずに1本の太い線に見えていた。寄せられない
  ときは逆に 2R 以上まで離して角の半径を確保する。直したあとの出口の間隔は 13〜15px。
- **葉の折り返し方を、木ぜんぶで1つではなくクラスタごとに選ぶようにした。** これまでは
  「1列あたりの行数」を木全体で1つしか持てず、葉12体の班と葉7体の班が同じ折り返しを
  強いられて、どちらにとっても最良でない形で釣り合っていた。束ごとに選べるようにすると、
  測った5通りの枠すべてで拡大率が上がるか同じで、最大 0.360 → 0.430（+19%）。深い木の
  ダミーでも 0.270 → 0.300 ほか。クラスタが1つしかない木では結果が1桁まで完全に不変。
- 探索は総当たりではない。候補は「列数が変わる行数」だけに絞り（同じ列数なら行の多い
  ほうは幅が同じで高さだけ増えるので必ず負ける）、従来の「木ぜんぶで同じ行数」の最良から
  始めて1つずつ動かす。だから**従来の答えより悪くなることが構造的に無い**。同点のときは
  幅の狭いほうを採る——縦で効いている枠では列を1本減らしても拡大率が動かないことがあり、
  そこはただで幅が縮む（実測で 368px）。settleWrap 1回は45体の木で 0.22ms、探索は十数ms。

## 0.7.0

**稼働中のサブエージェントの様子を、実測で映すようにした。** 記録（state.json）が更新
されるのは「起動直後」と「完了通知時」の2点だけで、そのあいだ機体が本当に動いているのか、
詰まって止まっているのかは画面から分からなかった。運用ルールの制約表にも「実行中は無音」
「進捗は実測ソースが無いため出さない」と書いてあった。**その前提が間違っていた。**
あわせて、系統樹の葉を自動で折り返すようにし、配線を1種類の書式へ作り直した。

- **稼働中の実測は Claude Code 自身の記録から読む。** サブエージェント1体につき1本の
  JSONL が稼働中にそのまま追記されている（`<claude設定>/projects/<slug>/<sessionId>/subagents/agent-<agentId>.jsonl`）。
  ツール呼び出し1件ごとに1行増え、時刻・ツール名・引数・usage が入っている。ここから
  読めるのは全部実測値なので、**「推測値を書かない」という方針を崩さずに出せる**。
- 読み方はすべて実データで検証した。トークンは累積合計ではなく**最後の assistant 行の
  `input + cache_creation + cache_read`**（＝そのときの文脈長）。`cache_creation` は5分で
  失効する一時キャッシュなので、単純合計は実際の 2.8〜45 倍に膨れる。完了通知の値と
  n=8 で 947,275 対 947,297（誤差 -0.002%）。ツール回数は `tool_use` の数と完全一致
  （288 対 288）、所要秒は最初と最後の時刻の差で誤差 13ms 以内。
- **どの実機がどのカードかを確信できないときは、何も載せない。** 別の機体の数字を
  カードに出すのが最悪の結果なので、「分からない」を「たぶんこれ」より優先する。記録に
  無いのに動いている機体は、系統樹には入れず別枠に出す（親を推測して描いたら実測でなくなる）。
- 20体で6観点の敵対的レビューをかけ、反証を耐えた11件（うち重大7件）を直した。素性を
  丸ごと失っていた経路（実データで 475本中 37本、7.8%）や、別の機体の数字を記録に
  焼き付ける経路3つなど、**どれも画面を見ても気づけない壊れ方**だった。
- **系統樹の葉を自動で折り返し、枠いっぱいに使う。** 第1世代に何体も並ぶと縦にだけ伸び、
  拡大率の縦側だけが効いて全体が縮んでいた（指令塔＋10体で 47%）。子を持たない機体を
  列優先のグリッドへ折り返すことで、同じ形が 98%、16体では 29% → 78% になる。
- 折り返しの安全性は**実測で保証する**。置いてから測り、線がカードを貫くバンドだけ
  折り返しをやめる。さらに「扇が通る縦幅を場所取りする」案と「1列に戻す」案を実際に
  組んで低いほうを採るようにした（dummy-collision で +10% と +82% の差があった）。
- **配線を「直線＋角R」の1種類に統一した。** 幹線・送り線・レール・フックという4種の
  共有ジオメトリを廃し、1辺＝1本の独立した直交折れ線にした。共有線があると、そこを複数の
  機体が通るので状態色を載せられず（4体中1体の稼働で列の全長がシアンに見える）、分岐点で
  別の色・別の破線位相の線が重なる。1辺1本にすると、その2つは構造ごと消える。
- 角はすべて真円の四分円（半径14px）。実測で、曲率半径の中央値は 5.5px → 14.0px
  （＝設計値どおり）、別の線との並走は 45〜61% → 0.0%、カード貫通は 0、交差は 0〜1件。
- **2列目以降へ向かう辺は、クラスタの下を迂回する。** 上を迂回すると、読み手の視線が
  「第◯世代」→最初の行と流れるところへ横線束が割り込み、クラスタに入った直後がいちばん
  混む配置になっていた。下に回すと、その混雑は読み終えて次へ移る境目に来る。
- タブを初めて開いた直後に、線が古い座標のまま固まる問題を直した。隠れていた器を出した
  直後はカードの寸法と位置が 600ms ほど動き続けるので、止まりきるまで毎フレーム引き直す。
## 0.6.3

**イベントログを畳めるようにした。** 右のログは常に292pxを占めていて、系統樹を広く
見たいときに引っ込める手段が無かった。

- **トップバーに開閉ボタンを1つ足した**（`⛶` の隣の `◫`）。ボタンはパネルの外に置いて
  ある——中に置くと、閉じた瞬間に再び開く手段まで一緒に隠れる。
- 開閉は幅 292px ↔ 0 の transition で、畳んだ分だけ系統樹が横に広がる。状態は全チーム
  共通で `localStorage`（`dashboard:logOpen`）に持つので、タブを切り替えてもリロード
  しても畳んだままになる。
- **`display:none` は使っていない。** 配下の CSS アニメーションを取り消してしまい、
  ログ行の入場アニメーション（`.log-row` の `slidein`）が死ぬため。畳むのは幅と
  `opacity` と `border-left-width` だけで、`.team-side-inner` に固定幅を持たせて、
  縮む途中に中身が折り返し直されないようにしてある。
- `prefers-reduced-motion: reduce` のときは瞬時に切り替わる。

## 0.6.2

**変更履歴トラッキングを入れた。** Claude Code の hooks からツール呼び出しを拾い、
セッションごとの要約と `CHANGELOG.md` をプロジェクトの中に積み上げていく。これまで
ダッシュボードが映していたのは「いま誰が動いているか」だけで、**セッションが終わると
何をしたかは残らなかった**。

- **記録はプロジェクトローカル**（`<project>/.claude/changelog/`）。生ログ・セッション
  要約・`index.json`・`CHANGELOG.md` を置く。`index.json` と `CHANGELOG.md` は要約から
  いつでも作り直せる（`changelog_cli.py render`）。
- **本文は保存しない。** 残すのは追加/削除の行数（diffStat）までで、diff の全文や変更前の
  ファイルは記録に入れない。契約としてデータ層の冒頭に明記してある。
- **hooks はセッションを止めない。** `log-event` は何があっても exit 0、`stop-check` は
  「未要約の生ログがある」と判断したときだけ exit 2 で止める。argparse や import の失敗も
  含めて全ての脱出を捕まえてから終わる（`--phase` の打ち間違い1つで**すべての Bash が
  拒否される**事故が実際に起きたため）。
- **どのプロジェクトに履歴があるか**は、ホーム側の `changelog_registry.json` で辿る。
  プロジェクトローカル保存だけでは画面から見つけられないため。
- 画面はミッション管制室を `#mission-screen` という器に包み、変更履歴の面と並べた。
  既存の `#team-tabs` / `#teams-wrapper` / `#standby` とそのIDは変えていない。
- 拡張機能側は、ワークスペースを開いたときに変更履歴の初期設定を持ちかける。「初期設定を
  やり直す」でワークスペース単位の判断も一緒に消えるようにしてある（消し忘れると
  変更履歴側だけ前の判断が残り、`--reset` でも戻せない）。

## 0.6.1

**運用ルール本文に `--parent` の説明を入れた。** 本文には `add` の例が1つしか無く、
`--parent` にも孫エージェントにも触れていなかった。本文だけを読んだ指令塔は、何世代に
展開しても全員を指令塔直下として登録する。実際に4世代へ展開したチームが画面に1列しか
出ない事故が起きた。**表示側は正しく、書かれていないものが映らなかっただけである。**

- `--parent` を使った `add` の例を1行足した。既定値が「指令塔直下」であることは変えて
  いない（指令塔が自分で起動した機体には要らない）。
- **`add` は1体につき1回**を本文に明記した。「複数体を同時起動したら体数ぶん打つ」は
  これまで手引き側にしか無く、本文だけを読むと6体を1件にまとめてよいと読めた。まとめた
  1件は、その6体と配下に展開した機体を丸ごと失う。**あとから分解する手段は無い。**
- 孫の自己申告は、置き場所（`status` の末尾に出る）と、**サブエージェント自身のIDを
  `parentId` に書かせる**ことを本文に書いた。指令塔が子へ渡す指示文を、手引きを開かずに
  組み立てられる最小限にしてある。

本文が変わったので版を上げてある。上げないと、既に書き込まれている運用ルールが古いままで
あることを `start` / サーバー起動 / `diagnose` のどれも知らせられない。

## 0.6.0

**Claude Code 以外の AI コーディング CLI でも動くようにした。** 運用ルールの書き込み先を
`CLAUDE.md` 固定から、CLI ごとのレジストリへ置き換えてある。**このマシンに入っている対応
CLI を全部見つけて、それぞれの指示ファイルに同じ運用ルールを書く**（本文は同一で、置き場所
だけが違う）。

- **組み込みで10種**（Claude Code / Codex CLI / Gemini CLI / GitHub Copilot CLI / opencode /
  Amp / Cline / Roo Code / Windsurf / Qwen Code）。表に無い CLI が「非対応」にならないよう、
  利用者が足せる `agents.json` と `--agent-file` を用意した。同じ鍵なら利用者側が勝つので、
  CLI が置き場を変えても配り直しを待たずに直せる。
- `install.py --list-agents` で、知っている CLI 全部の状態が見られる。書き込む先を1つに絞る
  なら `--agent`、表に無い CLI を指すなら `--agent-file`。
- 取り消しは対応 CLI を全部見る。書く側が自動で増えるのに消す側を絞ると、消し残る。
- **セットアップ後に CLI を入れた場合を検知して知らせる。** 従来はここが緑のままで、画面に
  何も出ない理由に辿り着けなかった。`start` / サーバー起動 / `diagnose` の3経路。
- **司令塔のモデル ID を `claude-opus-5` で埋めるのをやめた。** 運用ルール側で `--model` を
  渡させる。分からない値を推測で埋めないという既存の原則を、ここにも適用した。

**言語設定が、すでに走っているセッションへ届くようにした。** 運用ルールはセッション開始時に
一度読まれるだけのスナップショットなので、`dash lang` で設定を直しても、走っているセッション
には何も届かない。設定を en から ja に変えたとき、指令塔の行は日本語なのに第1世代のサブ
エージェントは英語のまま、という混在が起きていた。

- 走っているエージェントに届く経路はコマンドの出力しかないので、`start` が毎回「自由記述は
  この言語で書く」を1行出す。`start` は1ミッションに1回なので、繰り返しで読み飛ばされる
  ことがない。
- `start` / `add` / `done` / `finish` が、渡された自由記述が設定言語で書かれていないように
  見えたら警告する。判定は文字種を見る当て推量なので警告に留め、書き込みは拒否しない。
- **`dash lang` が運用ルールも書き直すようになった。`dash install` の打ち直しは要らない。**
- 常駐している `server.py` が起動時の言語のまま出し続ける問題を直した。

**取扱説明書（画面の「？」）を、現行の実装に合わせて4言語とも書き直した。** 中身が実装から
取り残されていて、いくつかの節は現行と正反対のことを書いていた。

- **「画面に映るチーム」** — 「切り替える UI は無い」「複数チームを縦に積んで同時表示」と
  書いてあったが、実際にはタブ列があり、表示されるのは選んだ1枚だけ。本文・表・図・注記を
  実装どおりに直した。
- **「過去のミッションはどこまで残るか」** — 「直近1件のみ。`start` で上書き」と書いて
  あったが、実際はプロジェクトごとに最大20件を `history/` に残す
  （`AGENT_DASHBOARD_HISTORY_KEEP` で変えられる）。
- **コマンド表に `dash history` が無かった**ので足した。
- **「実測値しか出さない」にモデル名を足した。** この版で `--model` の自動補完をやめたぶん、
  説明にも「モデル名も同じ扱い」と書いていないと辻褄が合わない。
- 運用ルールの置き場所の説明を、複数 CLI 前提に改めた（差し込み変数も `{CLAUDE_MD}` →
  `{INSTRUCTION_FILES}`）。「Claude を再起動」のように単一 CLI を前提にした言い回しも、
  中立な表現に直した。

### 直した不具合

- **取扱説明書に自分のユーザー名が出ていた。** パスを伏せる仕組みは「参考情報」欄にしか
  掛かっておらず、コピペ用のコマンド例は実パスのまま出していた（コピペして実行できることを
  優先した設計）。説明書は画面共有や配布資料に写ることがあるので、伏せる側を優先する。
  ホームごと隠すのではなく**ユーザー名の1階層だけ**を `<username>` に置き換え、
  `C:\Users\<username>\.claude\agent-dashboard\…` とパスの形は残した。読み替えの注記は、
  伏せる対象が無い環境（ツールをホームの外に置いている場合）では出ない。

## 0.5.1

**エージェントの名前と任務内容を、何語で書くかを明示した。** 0.5.0 では `install.py` が
`CLAUDE.md` に書く案内のうち、`--name` の言語を名指ししていたのは日本語・中国語・韓国語
だけで、**英語版だけ何語で書くかを言っていなかった**（`<a readable name>` としか書いて
いない）。そのため表示言語を英語にしても、Claude は会話の言語に引きずられて日本語の名前を
書いていた。

- `CLAUDE.md` へ書く案内に、**自由記述（`--title` / `--name` / `--mission` / `--headline`）は
  この案内と同じ言語で書く**という項目を4言語ぶん足した。日本語版だけにあった
  `<日本語の名前>` という言い方はやめ、規則は1か所だけに置いてある（2か所に書くと、
  片方だけ直されて食い違う）。
- **記録は訳さない。** 名前と任務内容は Claude が書いた自由記述で、記録したとおりに画面へ

### 自動フォーカス

これまで拡大率は手動でしか変わらなかった。`autoFitZoom()` という関数は前から**書かれて
いた**が、**どこからも呼ばれていない死んだコードだった**（`FEATURE_GUIDE.md` は「自動で
50% まで縮む」と、動いている機能のように説明していた。動いていなかった）。

配線すれば済む話ではなく、繋いだ時点で壊れる作りだったので、書き直した。旧実装には
独立した欠陥が4つあった。

- **永久に往復した。** 新しい拡大率を `100 ÷ 比` という**絶対式**で決めていた。これは
  `Z(n+1) = K / Z(n)` の形なので `Z(n+2) = Z(n)`、つまり周期2で振動する。実際に
  100% ⇔ 39.68% を10回反復しても収束しないことを実測で確かめた
- **一度縮んだら二度と戻らなかった。** 拡大するかの判定に `.tree-scroll` の `scrollWidth` を
  使っていたが、`.tree-canvas` の `min-width: 100%` で枠の幅まで底上げされる値なので、
  「中身が枠より小さい」が成立しない。拡大側の枝はどの拡大率でも一度も通らなかった
- **座標系が混ざっていた。** 拡大の外側の幅と内側の幅を割り算していた
- **横しか見ていなかった。** 実際にこの画面で先に溢れるのは**縦**で、同じ世代に6体並ぶと
  縦が溢れる一方、横は5世代ないと溢れない。つまり最も起きる過密に何もしていなかった

書き直した版は、拡大率を**相対**で決める。`新しい拡大率 = いまの拡大率 × (枠 ÷ 中身)`。
中身のローカル寸法は拡大率に依らず、枠のローカル寸法は 物理寸法 ÷ 拡大率 なので、この式は
拡大率が約分されて消える ＝ **どこから始めても同じ答えに1歩で着く不動点**になる。往復が
「止まる」のではなく**起きない**。そのうえで、スクロールバーの出入り（`scrollbar-gutter:
stable` で発生源ごと断つ）、1% 刻みの丸め（不感帯）、毎秒増える機体（拡大側だけ 0.5 秒
待つ）に備え、最後の止めとして同じ寸法のまま4回動いたら手を引くようにした。

**手動の操作が常に勝つ。** `+`/`−`・数値入力・`Ctrl`+ホイールのいずれかを触ると、その場で
自動が降りる（`⛶` が消灯する）。操作していないのに大きさが変わり続けることはない。
`⛶` を押せば自動に戻り、その瞬間に枠へ合わせ直す。自動が算出した拡大率は保存しない
（次に開いたとき1フレームで計算し直せるので、保存しても情報量がゼロ。むしろ後で自動を
切ったときに、利用者が一度も選んでいない数値が残る）。

### 拡大率が 1%〜500%・1% 刻みになった

範囲が 50%〜200%・10% 刻みから広がった。ただし 1% 刻みをボタンだけで送ると
100%→500% が 400 回になるので、操作を3つに分けた。

- `+`/`−` は丸い数字の飛び石を踏む（100%→500% は 9 回）。**押しっぱなしで連続送り**
- 真ん中の数字をクリックすると**数値入力**になる。1% 単位の指定はここで一発
- 系統樹の上で `Ctrl`+ホイール。現在値に比例した歩幅なので、どの倍率でも同じ操作感
  （トラックパッドのピンチも同じ経路で拾える）

1% では文字もロボも読めず、クリック判定も潰れるが、**拡大率コントロールは拡大の外側に
あるので必ず操作でき、詰みにはならない**。自動フォーカスも仕様どおり 1% まで縮む。

### 拡大したときに親子線がカードから外れていたのを直した

**これは今回の変更で見つかった、以前からあった不具合。** `drawLinks()` は線の座標を
`getBoundingClientRect()` の差（**拡大後**の物理px）で計算する一方、SVG の `viewBox` は
`scrollWidth`（**拡大前**のローカルpx）で設定していた。この2つは拡大率の倍だけずれるので、
**100% 以外のあらゆる拡大率で線がカードから外れていた**（実測で 50% のとき 157px、
500% のとき 13,387px）。手動でしか拡大率が変わらなかった頃は 100% から動かさなければ
表に出なかったが、自動フォーカスは常時 100% 以外に留まるため、放置できない。
実測比で割ってローカル座標に戻すようにした。

速さと堅牢性の版。**消せない記録が消せるようになり、締め忘れが見えるようになり、

利用者からの報告で分かった不具合（要素 ID の食い違い1つで画面全体が沈黙する）は

起きても「一部のボタンが効かない」で済むようにし、出す前に機械が検める仕組みを足した。

### 画面が黙って死ななくなった

**v0.2.5 は、要素 ID の食い違い1つで画面全体が沈黙していた。** 直接の原因（JS 側の
セレクタが旧名のまま）は 0.3.0 で既に直っているが、**その1つで全部が止まる作り**は
そのまま残っていた。同じことが次に起きても「一部のボタンが効かない」で済むようにした。

なぜ1つの食い違いが全部を止めたのか。この画面は body 末尾の1本のインラインスクリプトで
出来ていて、top-level で例外が出るとそこから下が実行されない。そして**初期化（ポーリングの
開始）は最後の行にある**。途中で落ちると `fetch` が一度も飛ばず、右上は初期値の「接続中…」の
まま固まる。`tick()` の中ではないので try/catch にも掛からず、「切断」にすらならない。
利用者からは**サーバーの不調と見分けが付かない**ため、サーバーかポートかインストール先かの
切り分けに時間を使わせた。原因そのものは1行だった。

- **`need()` を通して要素を引く。** 見つからなくてもその場では落とさず、どのセレクタが
  無かったのかを控える。親が無いときは `document` へ落として**別物を掴まない**
  （食い違いが別の場所の誤動作に化けると、もっと追いにくくなる）
- **`bind()` で登録する。** 相手が居ないハンドラ登録を飛ばす
- **`boot()` を `DOMContentLoaded` からも呼ぶ。** このスクリプトは body の末尾にあるので、
  途中で落ちてもこの登録だけは済んでいる。**ポーリングは必ず始まる**
- **不具合を右上に出す。** 「画面に不具合」と赤く出し、`title` に**足りないセレクタ名**を
  入れる。拾えなかった例外も `window.onerror` で拾って出す。1秒ごとの `setConn` が
  これを「接続中」で塗り潰さないようにもした（塗り潰すと、また沈黙に戻る）
- **タブバーは系統樹を巻き込まない。** `renderTabs()` は `tick()` から呼ばれるので、
  ここで落とすと系統樹も機体数も一緒に止まっていた。付属品の欠けは付属品だけの問題にする

### 出す前に配線を検める（`check_wiring.py`）

**この間違いは人が気をつけて防げる種類のものではない。** 管制室は開いたまま放置する
ページで、1秒ごとにポーリングはするが自分をリロードしない。開いた状態で HTML の `id` を
書き換えても、すでに走っている旧スクリプトは影響を受けず動き続ける。破綻は**次に新規
ロードした瞬間**まで表に出ないので、改名した本人の画面では最後まで正常に見える。
ブラウザキャッシュの話ではない（サーバーは `Cache-Control: no-store` を返す）。
「古いものが配られた」のではなく「リロードされないまま出荷された」という形だった。

- `need()` が引いているセレクタが HTML に実在するかを検める道具を足した。
  `build_vsix.py` の `build()` が最初に呼ぶので、**食い違ったまま .vsix は作れない**
- 判定は `need()` を通ったものだけ。「静的な markup に必ずある」という約束なので、
  無ければ食い違いだと断定できる。動的に作る要素（`.tab-item` や `.agent`）は対象外
- セレクタの実在は markup 側だけで判定する。スクリプト内の文字列まで数えると、
  JS が自分で付けた名前を自分で確かめることになって見逃す
- 検査が落ちたときは古い `.vsix` を消す前に止まる（手元に何も残らない状態を作らない）
- 現行ソースで 23 個ぶんを確認。見張りが噛むことは変異試験で確認済み
  （HTML だけ改名／JS だけ旧名へ／入れ子の class 名ずれ の3通りで鳴り、健全なページでは鳴らない）

**「完了」と出ているタブが消せるようになった。** これまで画面から消せたのは `history/` に
退避済みの記録だけだった。`history/` へ移されるのは同じプロジェクトで次の `start` を打った
ときだけなので、**1度きりのミッションは完了しても現在の枠に残り続け、「完了」と表示されている
のに「✕」も付かず一括削除の件数にも入らない**（＝消す手段が画面に無い）状態だった。

- タブの「✕」と「完了した記録を削除」の対象を、`history/` の記録だけでなく**完了した現在の
  ミッション**（`state.json`）にも広げた。稼働中・待機中のものは今までどおり消せない
- `dashlib.delete_current_run(slug)` を追加。`phase` が `done` のときだけ `state.json` と
  `agents/` を `trash/` へ移す。`state.json` が読めないものも「完了」と確かめられないので消さない
- そのプロジェクトに `history/` の記録が1件も残らない場合は、空のフォルダを残さず
  **プロジェクトごと** `trash/` へ移す（削除前のダイアログでも断りが出る）
- 消したものが `.current`（映しているチーム）だった場合は、他の稼働中へ自動で付け替える。
  居なければ待機画面に戻る
- `POST /api/history/delete` が `runId: null` を受け付けるようになった。完了していないものを
