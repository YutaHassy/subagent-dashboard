# Subagent Dashboard

[English](README.md) | **日本語** | [中文](README.zh.md) | [한국어](README.ko.md)

Claude Code のサブエージェントが、いま何体動いていて、どれが終わって、
どれだけ時間とトークンを使ったのかをリアルタイムで見るためのローカルアプリです。
ロボットの表情と動きで状態が分かります。

- **外部ライブラリなし** — Python 標準ライブラリだけで動きます。`pip install` は不要です
- **インターネット不要** — CDN 参照ゼロ。オフライン環境でも動きます
- **PC を選びません** — Windows / macOS / Linux、Python 3.9 以降で動きます
- **置き場所を選びません** — フォルダごとコピーすればどこでも動きます（USBメモリでも可）

---

## 導入（2ステップ）

### 1. 初期設定（ウィザード形式）

フォルダを好きな場所に置いて、セットアップツールを実行します。

#### 推奨: 完全セットアップ（初期設定 + VSCode 拡張）

**Windows の場合:**
- `setup-full.bat` をダブルクリック

**macOS / Linux の場合:**
- `setup-full.sh` をダブルクリック

**これだけで以下がすべて完了します:**
1. Python 環境の検出
2. 初期設定（見つかった各 AI コーディング CLI の設定ファイルへの書き込み）
3. VSCode 拡張機能のインストール

#### 代替: 初期設定のみ（VSCode を使わない場合）

**Windows の場合:**
- `setup.bat` をダブルクリック

**macOS / Linux の場合:**
- `setup.sh` をダブルクリック

#### コマンドラインから実行する場合

```bash
# 完全セットアップ（Windows）
dash.cmd ext install

# 初期設定のみ（Windows）
dash.cmd install

# macOS / Linux
./dash install
```

**ウィザード形式のインストーラーが起動し、4つのステップで自動セットアップします:**

1. **環境チェック** — Python バージョン、ファイル構成、書き込み権限を確認
2. **環境の自動検出** — Python コマンド、パス、設定ファイルの場所を検出
3. **設定ファイルへの書き込み** — インストール済みの各 AI コーディング CLI の設定ファイルと VSCode キーバインドを更新
4. **セットアップ完了** — 起動方法と次のステップを案内

すべての項目に ✓ が付けば完了です。

- このフォルダの実際の場所を検出して埋め込むので、**別のPCでも同じコマンドで済みます**
- マーカーで囲んだ範囲だけを書き換えるので、各 CLI の設定ファイルの既存の記述は壊しません
- 書き込む内容を先に確認したい場合は `dash install --print`
- 取り消す場合は `python install.py --uninstall`

**🚀 自動セットアップ機能:**

初回実行時(サーバー起動時など)に未設定が検出されると、**自動的にセットアップを案内します。**
- 対話環境(ターミナルで直接実行)では、確認ダイアログが表示されます
- 非対話環境(Claude が実行)では、警告を表示して続行します
- VSCode 拡張機能を使う場合は、本体配置後に自動実行されます

**🔍 動作確認（診断ツール）:**

正しく設定されたか確認するには、診断スクリプトを実行してください:

```bash
python diagnose.py
```

ウィザード形式で6項目をチェックし、すべて ✓ になれば成功です。
問題が見つかれば、原因と解決策が番号付きで表示されます。

### 対応している AI コーディング CLI

セットアップは、マシンにインストール済みのすべての AI コーディング CLI を自動で検出し、
それぞれの設定ファイルに同じ運用ルールを書き込みます。以下のツールに対応しています。

| CLI | 書き込み先 |
| --- | --- |
| Claude Code | `~/.claude/CLAUDE.md` |
| Codex CLI | `~/.codex/AGENTS.md` |
| Gemini CLI | `~/.gemini/GEMINI.md` |
| GitHub Copilot CLI | `~/.copilot/copilot-instructions.md` |
| opencode | `~/.config/opencode/AGENTS.md` |
| Amp | `~/.config/amp/AGENTS.md` |
| Cline | `~/Documents/Cline/Rules/subagent-dashboard.md` |
| Roo Code | `~/.roo/rules/subagent-dashboard.md` |
| Windsurf | `~/.codeium/windsurf/memories/global_rules.md` |
| Qwen Code | `~/.qwen/QWEN.md` |

**この表にない CLI でも対応する方法があります。** `--agent-file` オプション（詳細は下の「セットアップのコマンドラインオプション」を参照）
で、任意のファイルを登録してください。

> **Cursor と Aider について**
> これらのツールはユーザーレベルの設定ファイルを読まないため、上の表に含まれていません。
> Cursor はリポジトリごとの `AGENTS.md` を読み、Aider は設定で明示的にファイルを指定する必要があります。
> これらのツールに対応させるには、リポジトリ内のファイルに `--agent-file` で指定してください。

### セットアップのコマンドラインオプション

`install.py` をコマンドラインから実行するときのオプション：

```bash
python install.py --list-agents           # 見つかった全ての CLI、書き込み先、状態を表示
python install.py                         # このマシンにインストール済みの CLI に書き込む
python install.py --agent codex           # 特定の CLI（この例では Codex CLI）のみに書き込む
python install.py --agent all             # 全ての既知の CLI に書き込む（インストール状況に関わらず）
python install.py --agent-file <パス>     # 指定したファイルにも書き込む（対応していない CLI 用）
```

`--agent-file` で登録したファイルは `agents.json`（記録の保存先の隣に置かれる）に永続的に記録され、
以降は `--list-agents` に表示され、次に `install.py` を実行するときに更新され、`--uninstall` で片付けられます。
`agents.json` を手で編集することもできます。組み込みの設定と同じキーを持つエントリは組み込みを上書きします。

### セットアップ後に新しい CLI をインストールした場合

セットアップは、その時点でマシンにインストール済みの CLI を検出します。**セットアップ後に新しい AI CLI をインストールすると、
それには運用ルールが書き込まれていない状態になります。** サブエージェントを起動しても、そのダッシュボードに何も表示されません。

**解決策は1行：** `python install.py` をもう一度実行してください。このツールは新しく見つかった CLI に運用ルールを書き込みます。

ツール本体も検出します。セットアップの際にマシンに見つからなかった CLI がインストールされた場合、次の以下のタイミングで警告が出ます：

- `dash start` を実行したとき
- サーバーを起動したとき
- `python diagnose.py` を実行したとき（インストール済みだが未設定の CLI がある場合は失敗扱いになります）

### 2. 画面を開く

```bash
# Windows
dash.cmd serve --open

# macOS / Linux
./dash serve --open
```

ブラウザが開きます。この窓は起動したままにしておいてください。
サーバーは**1つ起動すれば、どのプロジェクトで作業していてもこの画面に出ます。**

あとは普段どおり Claude に作業を頼むだけです。サブエージェントが起動されると、
その場でロボットが現れます。

画面に映るのは**いま動いているチーム**です（複数のプロジェクトが同時に動いていれば、全部タブに並びます）。
作業が終わってもそのまま残り、次に同じプロジェクトで作業を始めると、前の記録は消えずに
タブの「過去の記録」として残ります。何も動いていないときは待機画面です。

## 使い方

**取扱説明書がアプリに同梱されています。** サーバーを起動して次を開いてください。

```text
http://127.0.0.1:3939/manual.html
```

ダッシュボード画面の右上「?」ボタンからも開けます。
ロボットの表情の意味、カードの読み方、困ったときの対処が図入りで書かれています。

### よく使うコマンド

`dash` は Windows では `dash.cmd`、macOS / Linux では `./dash` です。

| コマンド | 内容 |
| --- | --- |
| `dash serve --open` | 画面のサーバーを起動してブラウザを開く（`Ctrl+C` で停止） |
| `dash serve --port 4000` | ポートを指定して起動する |
| `dash projects` | 登録済みプロジェクトの一覧。`→` が現在のフォルダの対象 |
| `dash status` | いまのプロジェクトの中身を表示 |
| `dash demo` | 表示確認用のダミーデータを入れる |
| `dash reset` | いまのプロジェクトを空にする |
| `dash history` | このプロジェクトの過去のミッション（`history/`）を一覧表示 |
| `dash install` | 初期設定（別のPCに移したときに実行） |

`dash` だけで実行すると一覧が出ます。各コマンドは `dash <コマンド> --help` で詳細が見られます。

状態を書き換えるコマンド（`start` / `add` / `done` / `finish`）は通常 Claude が自動で実行するので、
手で打つ必要はありません。

`dash autofinish` はこれとは別枠のコマンドです。SessionEnd hook から呼んで、**セッションが終わったら
稼働中のミッションを自動で締める**ために使います。締め忘れはこのツールで唯一あとから直せない壊れ方
なので（次に `start` した瞬間に「未完」のまま履歴へ押し出され、そこから完了にする手段が無い）、
人にではなくセッションの終わりに結びつけてあります。稼働中のミッションが無ければ何も出力せず終わり、
`--project` を省けばそのディレクトリで並行しているミッションを全部締めます。ただし締めるのは
自分が開いたミッションだけで、同じフォルダで動いている他のセッションのミッションは
（セッションIDが分かる環境では）黙って見送ります。設定例は
[OPERATION.ja.md](OPERATION.ja.md) を参照してください。

### 同じフォルダで2本を同時に走らせるとき

ミッションの記録先はプロジェクト（＝作業フォルダ）ごとに1つです。**別のセッションが
稼働中の記録を押し出そう・書き換えようとすると、いまは道具側が拒否します**（終了コード 1。
貼れば通る `--project` 付きのコマンドが案内に出ます）。押し通したいときだけ `--force` を
付けてください——いままでどおり押し出され、押し出された記録には「何に押し出されたか」が
残ります。この保護は `mission.sessionId`（`CLAUDE_CODE_SESSION_ID` 由来）が両側に揃っている
ときだけ効くので、古い記録や `CLAUDE_CODE_SESSION_ID` が渡らない環境では今までどおり無防備
です。並行させると分かっているなら、事前に `--project` で記録先を分けておくと衝突自体が
起きず、いちばん摩擦がありません。

```bash
dash start  --project issue51 --title "issue51 の調査" --model claude-opus-5
dash add    --project issue51 --id SCOUT-A --name "偵察A" --model claude-sonnet-5 --mission "..."
dash done   --project issue51 --id SCOUT-A --headline "..."
dash finish --project issue51 --headline "..."
```

`--project` は4コマンドすべてに付けます。1つでも付け忘れると、そのコマンドだけ現在のフォルダ側
＝もう一方のチームに書き込まれます。この手順は `dash install` が各 AI コーディング CLI の設定ファイルにも書き込むので、
エージェントも同じ規則で動きます。詳しくは [OPERATION.ja.md](OPERATION.ja.md) の
「6.1. 同じディレクトリで2本以上を同時に走らせるとき」を参照してください。

### 過去の記録を見る

同じプロジェクトで `start` をやり直しても、それまでの記録は消えません。
`missions/<プロジェクト>/history/<開始時刻>/` へ丸ごと退避され、画面のタブバーから選ぶと見返せます
（過去の記録は経過時間が止まった状態で表示されます）。

保持件数はプロジェクトごとに直近 20 件（既定）で、超えた分は古いものから `trash/` へ移動します
（`trash/` はフォルダを戻せば復旧できます）。一覧はコマンドでも確認できます。

```bash
dash history
```

## VSCode 拡張機能として開く（おすすめ）

VSCode の中に Subagent Dashboard のタブを出せます。ブラウザに切り替えなくて済み、サーバーの起動も拡張が面倒を見ます。

### 入れる（1回のみ）

```bash
# Windows
dash.cmd ext install

# macOS / Linux
./dash ext install
```

そのあと VSCode を再読み込み（`Ctrl+Shift+P` → Reload Window）してください。

npm も `vsce` も要りません。`.vsix` を Python の標準ライブラリだけで組み立てて `code --install-extension` に渡しています。

### 使う

左端のアクティビティバーに増えた**ロボットのアイコン**を押すと、エディタのタブに Subagent Dashboard が出ます。
左側に細長く置いておきたいときは、設定 `agentDashboard.sidebarBehavior` を `embed` にするとサイドバーの中に出ます。

コマンドパレット（`Ctrl+Shift+P`）で「Subagent Dashboard」と打っても同じです。

| コマンド | 何をするか |
|---|---|
| Subagent Dashboard: タブで開く | エディタのタブに Subagent Dashboard を出す |
| Subagent Dashboard: ブラウザで開く | OS の既定ブラウザで開く |
| Subagent Dashboard: サーバーを再起動 | この拡張が起動したサーバーを止めて立て直す |
| Subagent Dashboard: サーバーを停止 | この拡張が起動したサーバーを止める |
| Subagent Dashboard: 本体を配置／更新 | 同梱している本体を配置先へ置く |
| Subagent Dashboard: 初期設定を実行 | 初期設定（`install.py`）を確認のうえ実行する |
| Subagent Dashboard: 初期設定のフラグをリセット | 「もう済んでいる」記録を消し、次回また実行する |
| Subagent Dashboard: ログを表示 | 起動の経過と Python 側の出力を見る |

サーバーが動いていなければ拡張が起動します。すでに動いていればそれを使い回すので、プロセスが増えていくことはありません。ポートが埋まっていれば次の番号へ繰り上げ、その番号で画面を開きます。

外（ターミナルの `dash serve` など）で立てたサーバーは、拡張は使い回すだけで勝手に止めません。

### 人に配る

拡張機能には**ダッシュボード本体が丸ごと入っています**。相手の PC に何も無くても、これ1つで動きます。

```bash
dash.cmd ext package
```

`dist/` に 2 つのファイルが出ます。**これをメールに添付してください。**

- `agent-dashboard-<版>.vsix` — 拡張機能本体（約 0.1MB）
- `インストール手順.txt` — そのまま渡せる手順書

受け取った人は VSCode の画面だけで入れられます（拡張機能パネル → `…` → 「VSIX からのインストール...」）。
`code` コマンドは要りません。

初回にアイコンを押すと「本体をここに置きます」と確認が出て、承諾すると `~/.claude/agent-dashboard` に展開されます。**同梱物の場所では動かしません。** 拡張フォルダの名前にはバージョン番号が入っていて、更新するとフォルダごと変わるため、そこに記録を置くと消えてしまうからです。

更新版を配るときも同じ手順で上書きできます。`missions/`（作業の記録）には触れません。

**更新のときは、運用ルール（各 AI コーディング CLI の設定ファイル）も配り直されます。** 本体を新しくしても、
エージェントが読む手順書は前の版のまま残るためです（初期設定は一度成功すると自動では二度と走りません）。
拡張から更新すると、本体を置いたあとに「何をどこに書くか」の確認が続けて出るので、承諾するとそれぞれの
設定ファイルのマーカー内が新しい手順に差し替わります。見送った場合や、拡張を使わずに上書きコピーで更新した
場合は、手で実行してください。

```bash
python ~/.claude/agent-dashboard/install.py
```

古いまま使っていると `start` のときとサーバー起動時に知らせが出ます。いま揃っているかは
`python diagnose.py` の「運用ルールの版」で確認できます。

> `.vsix` は中身が ZIP なので、社内のメール関門に止められることがあります。
> その場合は拡張子を変えて送り（例 `.vsix` → `.txt`）、受け取った側で戻してもらってください。

### その他のコマンド

```bash
dash ext build       # .vsix を作るだけ（dist/ に出る）
dash ext status      # 入っているか、版が合っているか確認する
dash ext uninstall   # 抜く
```

拡張の設定・トラブルシューティングは [extension/README.md](extension/README.md) を、設計の経緯は [EXTENSION_PLAN.md](EXTENSION_PLAN.md) を見てください。

## グローバルアクセス（Global Access）

拡張機能を入れない場合の導線です。任意のプロジェクトフォルダから、ダッシュボードを素早く開けます。

### 概要

`dash install` コマンドで初期設定を行うと、**どのプロジェクトで作業していても** `Ctrl+Shift+D` を押すだけでダッシュボードが開きます。
agent-dashboard フォルダを開き直す必要はありません。

> `Ctrl+Shift+D` は VSCode 標準の「実行とデバッグ」ビュー（`workbench.view.debug`）と同じキーです。
> `dash install` を実行するとこちらが優先され、デバッグビューはそのキーで開かなくなります。
> 拡張機能を使う場合はキーバインドを登録しないので、この衝突は起きません。
>
> **以前の版では、この登録が効かない不具合がありました。** `install.py` が VSCode の読まないファイル（拡張機能の置き場）にキーバインドを書き込んでいたためです。書き込み先を OS ごとの正しいユーザー設定ファイルに直してあります。

### セットアップ（1回のみ）

agent-dashboard のディレクトリで次を実行します。

```bash
# Windows
dash.cmd install

# macOS / Linux
chmod +x dash        # 初回のみ
./dash install
```

これで以下が設定されます：

- **キーバインディング登録**: VSCode で `Ctrl+Shift+D` にダッシュボード起動アクションを割り当てます
- **任意のプロジェクトからアクセス可能**: VSCode がどのワークスペースを開いていても、同じショートカットで起動できます

### 使い方

1. **任意のプロジェクトを VSCode で開きます**

2. **`Ctrl+Shift+D` を押します**

   ダッシュボードが自動で起動してブラウザ（または SimpleWebService）に表示されます。
   
   初回起動時はサーバーが起動する際に数秒かかります。

3. **あとは通常どおり Claude に作業を依頼します**

   サブエージェントが起動されると、ダッシュボードにロボットが現れます。

### 仕組み

- **環境変数 `AGENT_DASHBOARD_HOME`** で agent-dashboard の場所を記憶します
- **`open_dashboard.py` スクリプト** がサーバーを起動し、ブラウザを開きます
- **ヘルスチェック** で http://127.0.0.1:3939 の応答を確認してから開きます

### トラブルシューティング

| 問題 | 対処 |
| --- | --- |
| `Ctrl+Shift+D` が効かない | VSCode の設定で「キーバインディング」を開き、`openDashboard` を検索して登録状況を確認してください |
| ダッシュボードが開かない | ターミナルを開いて `dash serve --open` を直接実行してください |
| ポートが使用中で起動できない | `--port 4000` オプションで別のポートを指定してください: `dash serve --port 4000 --open` |
| 手動で開きたい | ターミナルで `python <agent-dashboard-path>/open_dashboard.py` を実行してください |

## 設定

### 記録の保存先を変える

既定ではこのフォルダの `missions/` に保存します。
このフォルダが書き込み不可の場所（`Program Files` など）にある場合は、
OS 標準のユーザーデータ領域に自動でフォールバックします。

明示的に指定したい場合は環境変数を使います。

```bash
# Windows (PowerShell)
$env:AGENT_DASHBOARD_HOME = "D:\dashboard-data"

# macOS / Linux
export AGENT_DASHBOARD_HOME=~/dashboard-data
```

### その他の環境変数

| 変数 | 効果 |
| --- | --- |
| `AGENT_DASHBOARD_HOME` | 記録の保存先 |
| `AGENT_DASHBOARD_PROJECT` | 対象プロジェクトを固定する（`--project` が優先） |
| `AGENT_DASHBOARD_HISTORY_KEEP` | 過去の記録をプロジェクトごとに何件残すか（既定 20。`0` で退避しない） |
| `PORT` | サーバーの既定ポート（`--port` が優先） |
| `CLAUDE_CONFIG_DIR` | Claude Code の `CLAUDE.md` の場所 |
| `CODEX_HOME` | Codex CLI の `AGENTS.md` の場所 |
| `GEMINI_CLI_HOME` | Gemini CLI の `GEMINI.md` の場所 |
| `COPILOT_HOME` | GitHub Copilot CLI の設定ファイルの場所 |
| `OPENCODE_CONFIG_DIR` | opencode の `AGENTS.md` の場所 |
| `AGENT_DASHBOARD_AGENTS_FILE` | 自分で追加した CLI のリスト（既定：`agents.json`、記録の保存先の隣） |

### 表示言語

英語・日本語・中国語（簡体）・韓国語に対応しています。**何も設定しなくても環境に合った言語で出ます。**

- **画面（ダッシュボード・取扱説明書）** — 右上の言語セレクタで切り替えます。初回はブラウザの言語設定から自動で決まり、選んだあとはこのブラウザに保存されます（サーバー側の設定とは独立です）。
- **コマンドの出力** — `dash lang` で今の言語と、それが**どこから決まったか**が出ます。変えるときは言語コードを付けます。

```bash
dash lang        # 今の言語と決まり方を見る
dash lang en     # en / ja / zh / ko
```

決まり方は上から順で、**最初に決まったものが使われます**。

| 順 | 決まり方 |
| --- | --- |
| 1 | 環境変数 `AGENT_DASHBOARD_LANG` |
| 2 | `dash lang <コード>` で保存した設定 |
| 3 | 環境変数 `LC_ALL` / `LC_MESSAGES` / `LANG` |
| 4 | OS の表示言語 |
| 5 | 英語 |

環境変数のほうが保存した設定より強いので、`dash lang ja` を実行しても変わらない場合は `AGENT_DASHBOARD_LANG` が設定されています（`dash lang` がその旨を表示します）。

**エージェントの名前と任務内容は翻訳されません。** これらはエージェントが `dash add` で書き込む自由記述で、書いたとおりに記録され、記録したとおりに画面へ出ます。エージェントが何語で書くかは `install.py` が各 AI コーディング CLI の設定ファイルに入れる記述で決まり、その記述は上の**コマンドの出力**の言語に従います——画面の言語ではありません。右上のセレクタを切り替えても変わらないのはこのためです。変えるのは `dash lang <コード>` で、**その場で記述も新しい言語に書き直されます**（設定した言語＝チームを組む言語になります）。

```bash
dash lang ja          # 1. 言語を決める（記述もこの言語に書き直される）
                      # 2. エージェントのセッションを再起動する（設定ファイルは起動時に読まれる）
```

書き直されるのは**このコピーを指している記述だけ**なので、別のコピーで言語を変えても設定ファイルの向き先が
別ディレクトリに変わってしまうことはありません。「運用ルールはどこにも書かれていない」と出たら、そのコピーは
まだ初期設定していないので `python install.py` を1回実行してください。

**既にある記録は書かれたときの言語のまま**です。あとから訳し直すと、画面が「実際に起きたこと」と違うものを映すことになります。

訳が用意されていない文は英語のまま出ます。**翻訳の抜けでコマンドが止まることはありません。**

## 仕組み

```text
Claude がサブエージェントを起動 / 完了通知を受信
        │
        ▼
  update_state.py  ──書き込み──▶  missions/<プロジェクト>/state.json
                     │             missions/<プロジェクト>/agents/*.json（孫の自己申告）
                     │
                     └─ start のたびに、それまでの記録を丸ごと退避
                                    missions/<プロジェクト>/history/<開始時刻>/
                                          │
                                     読み取り・マージ
                                          ▼
                                    server.py  ──▶  /api/state（進行中のチーム＋タブ一覧）
                                                  ──▶  /api/run（過去の記録1件）
                                                        │
                                                  1秒ごとに取得
                                                        ▼
                                                  public/index.html
```

- 状態の書き込み口は `update_state.py` だけ。時刻・世代・集計はすべて自動計算されます
- 書き込みは一時ファイル経由で差し替えるので、読み取り中に壊れたJSONを読むことがありません
- 孫エージェントは自分専用のファイルに書くので、書き込みが衝突しません
- プロジェクトの識別は「フォルダ名 + フルパスのハッシュ6桁」。同名フォルダでも混ざりません

### 表示しないもの

サブエージェントは作業中に進捗を報告しません。つまり進捗％の実測値は存在しないので、
**それらしい数字を作って表示することはしません。進捗バーそのものを置いていません。**
稼働中かどうかは、ロボの動きとカードの色だけで示しています。

例外は「報告待ち」（稼働中の手下を抱えている機体に付く琥珀色の表示）で、これだけは
**記録された親子関係からの導出**です。数字を捏造しているわけではありませんが、
「子が動いている」は事実でも「親が待っている」は推測なので、親が並行して自分の作業を
しているときは実態とズレます。

同じ理由で、完了通知に含まれなかったトークン数やツール使用回数は `—` と表示します。
これは故障ではなく「不明」という正しい表示です。

### 機体の色はモデルを表す

卵型のボディと腕の色は、動かしているモデルを表します。赤 = Fable、オレンジ = Opus / Sol、
薄緑 = Haiku / Luna、水色 = Gemini、白 = Sonnet / Terra とそれ以外、という対応です。

目・バイザー・アンテナ・胸ライト・口・状態のアニメーション（待機／稼働／報告待ち／完了）は
変えていません。そこは「状態」を表す場所なので、同じ場所に「モデル」という意味を重ねると
2つが競合するためです。

判定できないモデル名は白のまま落とします。推測して別の色に塗ると、画面が黙って嘘をつく
ことになるからです。hook が登録した機体のようにモデルが記録されていない機体も白になり、
それが正しい表示です。

状態のグロー（稼働のシアン／報告待ちの琥珀／完了のミント）はボディ色の上にそのまま乗るので、
色分けが状態の読み取りを潰すことはありません。

### 締めると記録に無い機体を焼き付ける

`finish`（と `dash autofinish`）は、ミッションを完了にする**前**に、そのとき動いていて記録に無い
機体を `state.json` に焼き付けます。稼働中のミッションしか実測を読まないので、焼き付けないと
締めた瞬間にその機体は画面からも履歴からも消え、いたこと自体が残りません。焼き付けたものは締めた
ときと同じ場所に、**完了した姿**（そこまでに測れていた所要・トークン・ツール回数はそのまま）で
残ります。機体数には数えません。

## トラブルシューティング

### ダッシュボードが反映されない

**症状:** Claude がサブエージェントを起動しても、ダッシュボードに何も表示されない

**原因チェック:**

1. **`install.py` を実行しましたか?**
   
   配布先のマシンで必ず1回実行する必要があります:
   
   ```bash
   cd <ダッシュボードの場所>
   python install.py
   ```

2. **診断スクリプトを実行してください:**
   
   ```bash
   python diagnose.py
   ```
   
   すべてのチェックが ✓ になっているか確認してください。

3. **エージェントのセッションを再起動してください**
   
   設定ファイルの変更は起動時に読み込まれるため、実行中のセッションには反映されません。

4. **カレントディレクトリを確認してください**
   
   ダッシュボードは**作業中のプロジェクトのディレクトリ**から対象プロジェクトを判定します。
   
   ```bash
   dash projects
   ```
   
   `→` マークが付いているプロジェクトが現在の対象です。

### 相対パスで動かしたい

相対パスでは動きません。理由は、Claude が実行するコマンドが**作業中のプロジェクトのディレクトリ**で実行されるためです。

**解決策:**

1. **`install.py` を実行する(推奨)**
2. **環境変数 `AGENT_DASHBOARD_HOME` を設定する**
3. **グローバルラッパースクリプトを PATH に追加する**

上記 1・2 の詳細は、上の「導入」節と「設定」節を参照してください。

### ポートが使用中で起動できない

```bash
dash serve --port 4000
```

別のポート番号を指定してください。サーバーは自動で繰り上げますが、明示的に指定することもできます。

### 配布後、他のユーザーのマシンで動かない

**必ず配布先のマシンで `install.py` を実行してもらってください。**

`install.py` は以下を自動検出します:

- Python のコマンド名(`python`, `python3`, `py -3`)
- ダッシュボードの配置場所(絶対パス)
- OS 固有の設定

これらは環境ごとに異なるため、配布元のマシンで作った設定は他のマシンでは動きません。
