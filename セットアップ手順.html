Subagent Dashboard
配布後のセットアップ手順

現行版 v0.4.2
vsix をインストールするだけで、あとは画面の確認に答えるだけです。 手動でコマンドを打つ必要はありません。ダッシュボード本体は拡張機能の中に入っているので、別途の準備も要りません。

必要なもの

  • Visual Studio Code 1.74.0 以降
  • Python 3.9 以降 — コマンドプロンプトで python --version が動けば大丈夫です

1. vsix をインストール

方法：VSCode の拡張機能パネルから

  1. VSCode を開く
  2. Ctrl+Shift+X で拡張機能パネルを開く
  3. パネル右上の … メニューをクリック
  4. 「VSIX からのインストール...」 を選択（英語表示のときは Install from VSIX...）
  5. agent-dashboard-0.4.2.vsix を選択
  6. 「…が正常にインストールされました」と出たら完了。求められたら VSCode を再読み込みしてください

代替方法（コマンドライン）：

code --install-extension "agent-dashboard-0.4.2.vsix"
添付が別の拡張子に変えられて届いた場合。 .vsix は中身が ZIP なので、社内のメール関門に止められて拡張子を変えられることがあります。 ファイル名を agent-dashboard-0.4.2.vsix に戻してからインストールしてください。

2. 初回起動 — 確認は2つ出ます

左端の縦並びアイコンにロボットの顔が増えているので、押してください。順に2つの確認が出ます。

ロボットのアイコンを押す　→　❶ 本体の配置　→　❷ 初期設定　→　Subagent Dashboard が表示される

❶ 本体をどこに置くか

Subagent Dashboard の本体をこの場所に置きます: C:\Users\<あなたの名前>\.claude\agent-dashboard （拡張に同梱しているファイルをコピーします。以後の記録もここに溜まります）
ボタン: 「配置する」

「配置する」を押してください。 置き場所は次のとおりです。ここは拡張機能の更新に巻き込まれないので、作業の記録が消えません。

WindowsC:\Users\<あなたの名前>\.claude\agent-dashboard
macOS / Linux~/.claude/agent-dashboard

環境変数 AGENT_DASHBOARD_DEPLOY_DIR を設定すると、この置き場所を差し替えられます。

❷ 初期設定をしてよいか

配置に続けて、次のダイアログが出ます。ファイルのパスは実際の場所が入ります。

Subagent Dashboard の初期設定を行います。よろしいですか？ 次の2つのファイルに設定を書き込みます。 1. C:\Users\<あなたの名前>\.claude\CLAUDE.md Claude Code に Subagent Dashboard の使い方を教える文章です。目印で囲んだ範囲だけを 書き換えるので、いま書かれている他の内容は消えません。 2. C:\Users\<あなたの名前>\AppData\Roaming\Code\User\keybindings.json Ctrl+Shift+D で Subagent Dashboard を開けるようにします。同じキーが既にあれば触りません。 元に戻すには: python "...\install.py" --uninstall
ボタン: 「設定する」「今後たずねない」

「設定する」を押してください。 実行されるのは次のとおりです。

  • Python の起動コマンドを実測で判定（python / python3 / py -3）
  • CLAUDE.md に運用ルールを書き込む（目印で囲んだ範囲だけなので、既存の記述は壊れません）
  • VSCode のユーザーキーバインドに Ctrl+Shift+D を登録する
  • macOS / Linux ではランチャ ./dash に実行権限を付ける
  • 書き込み先の確認と動作チェック
ダッシュボードサーバーはここでは起動しません。 サーバーは、サイドバーを開いたときや「タブで開く」を実行したときに自動で立ち上がります。

キーバインドの書き込み先

VSCode が実際に読む場所に書きます。OS ごとに違います。

Windows%APPDATA%\Code\User\keybindings.json
macOS~/Library/Application Support/Code/User/keybindings.json
Linux$XDG_CONFIG_HOME/Code/User/keybindings.json（未設定なら ~/.config/Code/User/）
~/.vscode/keybindings.json ではありません。 ~/.vscode は拡張機能の置き場であって設定の置き場ではなく、そこに keybindings.json を置いても VSCode は読みません（実測で確認済み）。0.2.x までの install.py はここに書いてしまっていました。 古い手順書を見ている場合はご注意ください。

キーバインドは拡張機能の contributes.keybindings ではなくユーザー設定に書きます。 VSCode 標準の Ctrl+Shift+D「実行とデバッグ」より確実に優先させるためです。

完了すると

Subagent Dashboard: 設定完了。CLAUDE.md に使い方を書き込み、Ctrl+Shift+D で開けるようにしました。
ボタン: 「Subagent Dashboard を開く」「ログを見る」

見送ってもSubagent Dashboard そのものは使えます。 あとから実行したくなったら、コマンドパレットの 「Subagent Dashboard: 初期設定を実行」を選んでください。 ただし Ctrl+Shift+D は、この初期設定を実行した場合にだけ効きます。

セットアップが完了したら

以降は、どのプロジェクトを開いていても、以下の方法で Subagent Dashboard にアクセスできます。

  1. アクティビティバー — 左端のロボットアイコンをクリック
  2. ステータスバーのボタン — 画面下の 🤖 Subagent Dashboard をクリック（動作中はポート番号も出ます）
  3. キーボードショートカット — Ctrl+Shift+D（初期設定を実行した場合のみ）
  4. コマンドパレット — Ctrl+Shift+P → 「Subagent Dashboard」と入力

よくある質問

Q: 確認のダイアログが出ません

A: 以下を確認してください:

  1. VSCode を再読み込みしましたか？
    • Ctrl+Shift+P → "Reload Window"
  2. 拡張機能がインストールされていますか？
    • Ctrl+Shift+X（拡張パネル）で「Subagent Dashboard」を検索
    • 「local.agent-dashboard」が表示されていれば OK
  3. 設定で自動セットアップが有効ですか？
    • Ctrl+Shift+P → 「基本設定: 設定を開く」
    • agentDashboard.runSetupOnFirstRun を検索（既定は true）

ダイアログを見逃しても、ロボットのアイコンを押せば画面上のボタンから同じことができます（下の「トラブルシューティング」を参照）。

Q: 「今後たずねない」を選んでしまいました

A: コマンドからいつでも実行できます:

Ctrl+Shift+P → "Subagent Dashboard: 初期設定を実行"

また尋ねるように戻したい場合は「Subagent Dashboard: 初期設定のフラグをリセット」を実行してください。

Q: 「配置する」を押しそびれました

A: ロボットのアイコンを押すと出る画面で「本体を配置して初期設定」を押すか、コマンドから実行してください:

Ctrl+Shift+P → "Subagent Dashboard: 本体を配置／更新"

Q: Python が見つかりません

A: Python 3.9 以降を入れてください。入れてあるのに出る場合は設定で指定します:

Ctrl+Shift+P → 「基本設定: 設定を開く」
`agentDashboard.pythonPath` に、Python の実行ファイルの完全パスを入力

例: C:\Users\YourName\AppData\Local\Programs\Python\Python310\python.exe

Q: Ctrl+Shift+D が効きません

A: 初期設定を実行していないと効きません。 「Subagent Dashboard: 初期設定を実行」を実行してください。 なお、初期設定をしなくてもロボットのアイコンとコマンドパレットからは開けます。

ご自身で ctrl+shift+d に別のコマンドを割り当てている場合、そちらが優先されるので Subagent Dashboard は開きません。

Q: 同じ作業フォルダで2つのミッションを同時に走らせたい

A: ミッションの記録先はプロジェクト（＝作業フォルダ）ごとに1つしかありません。 そのまま2本目を始めると、1本目は稼働中のまま履歴へ押し出され、以後書き込めなくなります （あとから完了に直す方法もありません）。並行させる場合は、Claude に start --project <一意な名前> のように記録先を分けさせてください。 start / add / done / finish の すべてに同じ --project を付けます。手順は初期設定で CLAUDE.md に書き込まれる 運用ルールに含まれています（v0.4.2〜）。

Q: 拡張を更新したら、CLAUDE.md の運用ルールはどうなりますか

A: 本体（コード）とは別に古くなるので、そのままでは更新されません。 v0.4.2 以降は、更新のあと初期設定の確認がもう一度出るので、そこで承諾すれば 目印で囲んだ範囲だけが最新に差し替わります。見送った場合は、あとから python ~/.claude/agent-dashboard/install.py を実行してください。 いま古いままかどうかは diagnose.py の「運用ルールの版」で確認できます。

Q: 設定を元に戻したい

A: 書き込んだ設定を取り消します:

python ~/.claude/agent-dashboard/install.py --uninstall

何が書き込まれるのかを事前に見たい場合は --print を付けると、変更せずに内容だけ表示します。

トラブルシューティング

「Subagent Dashboard を表示できません」と出て進まない

あきらめないでください。 その画面には理由と一緒に押せるボタンが並びます。 一番上のボタンは、表示されている理由をそのまま直す一手になっています。

理由一番上に出るボタン
本体がまだ配置されていない／配置を断った本体を配置して初期設定
設定 agentDashboard.home の指す場所に本体が無い設定 agentDashboard.home を直す
Python が見つからないPython の場所を設定する
ポートが全部埋まっているポート番号を変える
自動起動を切っている自動起動の設定を見る
.vsix に本体が同梱されていない本体の場所を設定する
サーバーが応答しないなど、時間を置けば通るものもう一度試す

その下には共通の道具が並びます（もう一度試す／本体を配置して初期設定（配置済みなら初期設定を実行）／設定を開く／ログを見る）。上から順に試してください。

理由に「この .vsix には本体が同梱されていないようです」と書かれていた場合は、添付そのものが不良品です。 設定を直しても解決しないので、送り主に本体入りの .vsix を作り直してもらってください。

画面が黒いまま変わらない／ログを確認する

Ctrl+Shift+P → "Subagent Dashboard: ログを表示"

ポートが使われていると出る

画面の一番上に出る「ポート番号を変える」を押すか、設定 agentDashboard.port を空いている番号に書き換えてください。 既定は 3939 で、使用中なら自動で次の番号へずれます（10個先まで探します）。

診断スクリプトを実行

環境の問題を自動判定します。この結果をそのまま送ってもらえると、配布元で原因を追えます。

python ~/.claude/agent-dashboard/diagnose.py

サーバーが起動しない

# 手動で起動してみる
python ~/.claude/agent-dashboard/server.py

消したいとき

拡張機能パネルで「Subagent Dashboard」を探してアンインストールしてください。 作業の記録は .claude/agent-dashboard に残ります。不要ならフォルダごと消してください。 CLAUDE.md とキーバインドへの書き込みは install.py --uninstall で取り消せます。

  • 本体を更新しても CLAUDE.md の運用ルールが古いまま残る問題を修正 — 更新のあと初期設定を配り直すか続けて尋ねるようにし、diagnose.py にも「運用ルールの版」の項目を追加
